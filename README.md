# JD 抢购客户端使用说明

这个项目现在已经不是“只会报错的老脚本”了。

按现在这版的实际验证结果，它已经可以做到：

- 在本机启动客户端页面
- 打开项目自己的“专用京东浏览器”
- 在专用浏览器里登录京东
- 把登录态同步回客户端
- 自动加购
- 自动进入购物车
- 自动进入京东结算页
- 自动定位 `提交订单` 按钮

默认是安全模式：

- 默认不会真的点击 `提交订单`
- 只会把你带到最后一步，避免误下单

如果你确认要真实下单，可以手动打开客户端里的 `自动点击提交订单`

## 一句话理解

你可以把这个项目理解成：

1. 先打开一个项目专用的京东浏览器
2. 在里面登录京东
3. 回到客户端填商品和地区
4. 点开始
5. 程序自动把你带到结算页
6. 要不要真的点提交订单，由你自己控制

## 先决条件

你电脑上需要有这些东西：

- Windows
- Chrome 或 Edge
- Conda
- Node.js / npm

如果你已经能正常运行 `conda`、`python`、`npm`，就够了。

## 第一次使用

### 1. 进入项目目录

在 PowerShell 里进入项目目录：

```powershell
cd D:\AI\JDPanicBuying
```

### 2. 创建项目专用 Python 环境

如果你还没有 `jd-conda-env`，先创建：

```powershell
conda --no-plugins create --solver classic -p "D:\AI\JDPanicBuying\jd-conda-env" python=3.11 -y
```

### 3. 安装 Python 依赖

直接运行：

```powershell
.\setup_env.bat
```

它会自动安装当前项目需要的依赖。

如果你想手动装，也可以：

```powershell
D:\AI\JDPanicBuying\jd-conda-env\python.exe -m pip install -r requirements.txt
```

### 4. 安装前端依赖并构建页面

第一次建议手动执行一次：

```powershell
cd frontend
npm install
npm run build
cd ..
```

只要 `frontend/dist/` 已经生成，以后一般不用反复 `npm install`。

### 5. 启动客户端服务

最简单：

```powershell
.\start_server.bat
```

如果你想手动启动：

```powershell
D:\AI\JDPanicBuying\jd-conda-env\python.exe runserver.py
```

### 6. 打开客户端页面

浏览器打开：

```text
http://localhost:12021/
```

## 正常使用流程

下面这套流程是现在推荐的傻瓜式用法。

### 第 1 步：先不要急着扫码登录

进入页面后，你会看到左侧“账户”区域。

你有 3 个和登录相关的按钮：

- `扫码登录`
- `打开专用京东浏览器`
- `检查专用浏览器状态`
- `从 Chrome 导入登录态`

推荐你优先使用：

1. `打开专用京东浏览器`
2. 在那个专用浏览器里完成京东登录
3. 回到客户端点 `检查专用浏览器状态`

如果弹窗提示：

`专用京东浏览器已登录。`

就说明这一步成功了。

### 第 2 步：填写商品信息

主界面里需要重点填这几个字段：

- `商品链接或 SKU`
- `地区 ID`
- `数量`
- `间隔秒`
- `重试`
- `并发`

#### 商品链接或 SKU

推荐直接填完整商品链接，例如：

```text
https://item.jd.com/100021044189.html
```

也可以只填 SKU：

```text
100021044189
```

#### 地区 ID

地区 ID 一定要按你自己的收货地区来填。

示例：

```text
12_965_38365_0
```

如果你不知道自己的地区 ID，可以参考：

[TEST/area_id](D:\AI\JDPanicBuying\TEST\area_id)

### 第 3 步：选择运行模式

页面里有两个模式：

- `有货自动下单`
- `定时下单`

#### 有货自动下单

适合：

- 商品平时缺货
- 一旦出现购买入口就立即尝试下单

#### 定时下单

适合：

- 你知道某个具体开售时间
- 想在指定时间点自动进入购买流程

如果你选 `定时下单`，要额外设置：

- `运行时间`

### 第 4 步：决定要不要真的提交订单

页面中间有一个很重要的开关：

`自动点击提交订单`

默认是关闭的。

#### 关闭时会发生什么

程序会：

- 自动打开商品页
- 自动加购
- 自动进入购物车
- 自动进入结算页
- 自动定位 `提交订单` 按钮

但是：

- 不会真的帮你点下去

这适合先验证流程是否通。

#### 开启时会发生什么

程序会在进入结算页后：

- 真实点击 `提交订单`

这一步可能会产生真实订单。

如果你只是想测试链路，先不要开。

如果你已经确认商品、地址、支付方式都没问题，再开。

### 第 5 步：先点一次“立即检测”

推荐第一次不要直接开跑，先点：

`立即检测`

它可以帮你先确认：

- 商品链接是否有效
- 页面是否还能访问
- 当前商品页是否出现购买入口

如果这里就报错，先不要点自动下单。

### 第 6 步：开始运行

确认登录态正常、商品正确、地区正确后：

- 有货模式就点 `开始自动下单`
- 定时模式就点 `启动定时下单`

## 页面上每个按钮是干什么的

### 账户区

#### `扫码登录`

老方式。

如果你直接用这个按钮，项目会尝试生成二维码并保存登录态。

现在京东风控更严格，所以更推荐你走：

`打开专用京东浏览器`

#### `打开专用京东浏览器`

会打开项目专用的 Chrome 会话。

它和你平时自己用的 Chrome 是隔离的。

用途：

- 专门给这个项目保存京东登录态
- 后续自动下单都尽量复用这份会话

#### `检查专用京东浏览器状态`

会检查：

- 专用浏览器是否已经登录
- 当前读到了多少登录 cookie
- 当前页面标题是什么

只要这里提示：

`专用京东浏览器已登录。`

就说明后续自动化链路可以用了。

#### `从 Chrome 导入登录态`

这是后备方案。

如果你已经在自己平时用的 Chrome 里登录了京东，可以尝试导入。

但更稳的方式还是专用浏览器。

### 配置区

#### `重置`

把当前表单恢复到默认值。

#### `立即检测`

只检测，不启动自动下单。

#### `开始自动下单 / 启动定时下单`

真正启动任务。

### 运行状态区

这里会显示：

- 当前 SKU
- 当前状态
- 当前库存判断
- 最近检查时间
- 错误信息

### 日志区

这里会显示服务端实时日志。

遇到问题先看这里。

## 推荐使用方法

如果你只想最稳地用，照着下面做：

1. 启动项目
2. 打开 `http://localhost:12021/`
3. 点 `打开专用京东浏览器`
4. 在专用浏览器里登录京东
5. 回客户端点 `检查专用京东浏览器状态`
6. 填商品链接和地区 ID
7. 保持 `自动点击提交订单` 关闭
8. 点 `立即检测`
9. 确认状态正常后，再点 `开始自动下单`

如果你确认真的要下单，再把：

`自动点击提交订单`

打开。

## 关于真实下单

如果你打开了：

`自动点击提交订单`

程序就会真的点击京东结算页里的 `提交订单`。

请你自己确认这些内容无误：

- 商品正确
- 收货地址正确
- 支付方式正确
- 价格可以接受
- 购物车里没有不想一起下单的其他商品

## 常见问题

### 1. 页面能开，但显示未登录

先点：

`检查专用京东浏览器状态`

如果提示没登录：

1. 点 `打开专用京东浏览器`
2. 在里面重新登录京东
3. 回来再点 `检查专用京东浏览器状态`

### 2. 商品页提示验证

这是京东风控导致的。

当前项目已经做了浏览器链路兜底，不再完全依赖旧的 `requests` 直连接口。

但如果京东验证太严格，仍然可能需要你人工在专用浏览器里先通过验证。

### 3. 能进入结算页，但不想真的提交

保持：

`自动点击提交订单 = 关闭`

即可。

### 4. 我想真的自动抢购

确认流程已经打通后，再开启：

`自动点击提交订单`

### 5. 默认商品不对

改这里：

[Config/config.ini](D:\AI\JDPanicBuying\Config\config.ini)

重点字段：

- `sku_id`
- `area`
- `amount`
- `buy_time`
- `submit_order`
